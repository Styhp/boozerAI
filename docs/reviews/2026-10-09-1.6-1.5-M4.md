- **Wording:** the empty result reads "No importers found by static analysis within depth N." A test fails on "will break", "safe", "no impact", "unused" or "dead code". Expansion is offered when results are depth-limited.

**C10, the type-only badge** (`src/client/components/ImpactPanel.tsx:53`). The "type-only path" badge appears whenever the *shown shortest chain* contains a `type-import`. A runtime chain may also exist, for example `main.ts` to `inventory.ts` at depth 2 (Agent B flagged this itself). A viewer reads "type-only path" as "runtime changes can't affect this file", which is false there.

**Fix, Agent B's choice:**

- **(a) Cheapest:** relabel the badge "shown chain includes a type import".
- **(b) Better:** run a second walk over non-`type-import` edges with the same depth limit, and show "type-only path" only for files that no runtime chain reaches.

Either way, add a test with the `main.ts` → `inventory.ts` case. The C1 contract field `includesTypeOnly` stays as defined; only the UI claim changes.
