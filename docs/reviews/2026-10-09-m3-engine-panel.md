## Blocking findings

**F1: no selected-file excerpt still produces an explanation.** `src/server/explain/retriever.ts:39–54` silently skips the selected file when its first whole line exceeds the remaining budget. `src/server/explain/service.ts:24–35` proceeds to the model regardless. Reproduced with a valid 2,027-byte one-line `large.ts`, within the 1 MiB cap: zero snippets, one model call, events `snippets → token → done`, and a finished answer with zero source. The labeled review model double supplies the answer; this proves the unsafe control flow, not that the actual model invented that particular sentence. `ExplanationPanel.tsx:153` also hides the snippet section at zero, so the absent context is not visibly explained. Fix: require a nonempty supported excerpt of the selected file before inference; if none fits, return a clear bounded-context failure/omission with no model call. Preserve exact line/hash provenance. Test a long first line both alone and with related files; increasing the budget alone leaves the same bug for longer supported lines.

**F2: a nonexistent root-relative path is silently linked to a different nested path.** `src/server/explain/validate.ts:27–31` applies basename-style suffix matching to paths with directory components. Reproduced with only `vendor/src/missing.ts` indexed: model prose `src/missing.ts` validates as linked to `vendor/src/missing.ts`, although the written path does not exist. This contradicts the validator's own lines 17–18 and the file-name check. Fix: after optional `./` normalization, directory-qualified names must match an exact snapshot path; only a bare basename may use a unique suffix. Flag the missing path rather than rewriting it through a link. Add exact-path, absent-qualified-path, unique/ambiguous basename and skipped-path cases.

Both repros used author-created in-memory data and trusted compiled product modules, with no target execution, runtime call or file modification. No engine/panel repair by this reviewer.
