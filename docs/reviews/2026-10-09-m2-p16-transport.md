## Code review

- `previewCloud` (`service.ts:48–64`) is synchronous and calls no adapter `stream`, so preview cannot reach the network.
- The two removed assertions ("no preview route", "session has no cloud field") were replaced because this task introduces exactly those contracts. The all-routes-need-a-token loop gained `explanations/preview`; no other check was dropped.
- The client caches cloud availability from the authenticated session, makes no background fetch, aborts previews on refresh or close, and maps every error to a fixed message.

## Non-blocking notes

- **N1 (carried over).** The preview hash binds the payload bytes; it does not prove the user saw the preview. That is now enforced only by the panel's "Send" step. A server-issued single-use preview ID would close it later.
- **N2.** With a key set, `/api/session` tells the token holder that a key is configured. That's intended for the panel; only the user's own browser holds the token.
- **N3.** Unexpected service codes map to HTTP 500 with the code string. All current codes are fixed enums, so nothing sensitive can appear.
- **N4.** The notes branch (P-17) changes the same two files. The merge must keep the preview route and session `cloud` field intact.
