## Code review

- **Safety:** `ts.createSourceFile` runs over supplied text, with no compiler host, Program or disk read. Target code is never executed. Snapshot validation re-hashes the source before parsing. Imports are only `node:crypto`, `node:module`, `typescript`, contracts and resolver, with no UI, server, storage or model code (boundary search: Pass). Outputs are frozen.
- **Correctness:** shadowed, reassigned and `eval`/`with`-scoped `require` calls become `ambiguous-require` rather than asserted edges. Hoisting and the TDZ are handled by collecting bindings across the whole scope before classifying calls. Statement-level evidence is checked by an automated test that the evidence lines contain the specifier (`tests/extractor.test.ts:47`). A parse error keeps its node and emits no edges. Zero denominators return `null`. Renaming a file produces exactly one new `not-found` edge.

## Condition C8 (Codex, before M2 shows real repositories; together with C7)

**Excluded files are reported as missing when the import omits the extension or uses `.js` for a `.ts` file.** `SnapshotResolver.resolve` checks the skip inventory only for the literal path (`src/shared/resolver.ts:48`), never for the extension and index candidates it just tried.

Probe on an inert temporary folder with `main.ts` importing `./credentials` and `./data.js`, where `credentials.ts` is skipped as `secret-name` and `data.ts` as `binary`. Both edges came back as `{"type":"unresolved","reason":"not-found"}`, counted as **failed** rather than **excluded**.

Extensionless imports are the norm in TS projects, so users will be told files are missing when Boozer deliberately excluded them. That contradicts ARCHITECTURE C1: "an exact candidate excluded by the snapshot rules counts as excluded … a missing path is `not-found`".

**Fix:** walk the existing candidate list in its documented precedence order and stop at the first candidate found in **either** the source files (→ `file`) or the skip inventory (→ `excluded`, with that candidate's path and reason). This is deterministic, not a guess. Add hand-written tests for an extensionless secret-name import, `.js`→`.ts` to a binary skip, an index file under an excluded entry, and (once C7 lands) an `oversize` skip. The 1.3 oracle has no such case and must still match unchanged.

## Non-blocking notes

- **N1.** `parseDiagnostics` (`extractor.ts:179`) is an internal TypeScript property. It's acceptable with the 6.0.3 pin, and it fails loudly if absent. Re-verify on any TypeScript upgrade.
- **N2.** `export type { X } from './a'` is recorded as `re-export`, not type-only, so impact chains through it won't set `includesTypeOnly`. Minor.
- **N3.** `import x = require('./a')` (older TypeScript style) is counted as `unsupported-syntax` rather than resolved. That's conservative and counted; consider supporting it after the hackathon.
- **N4.** An import whose case doesn't match the file name (`./Foo` against `foo.ts`) is `not-found`. That's correct for Linux portability. A distinct reason would explain it better.
- **N5.** `coverageRates` lives in `extractor.ts`, which imports the TypeScript compiler and `node:crypto`. The 1.5 UI at `e868ed3` doesn't import it (verified), but if any client code ever does, the browser bundle will pull in the compiler. Move display helpers to a client-safe module before the UI needs them.
